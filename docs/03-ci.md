# Continuous Integration

Run ReelOut in CI to automate releases when changes land on your main branch.
The examples below show the minimum setup; adapt permissions, secrets, and
package-manager steps to your project.

## GitHub Actions

Create `.github/workflows/release.yml`:

```yaml
name: Release

on:
  push:
    branches:
      - main
  workflow_dispatch:
    inputs:
      type:
        description: 'Specify the release type, bypassing automatic commit analysis.'
        type: choice
        options:
          - auto
          - major
          - minor
          - patch
        default: auto
      qualifier:
        description: 'Set or override the version qualifier (for example, alpha or beta); use false to disable.'
        type: string
      channel:
        description: 'Set or override the release channel (for example, stable or canary); use false to disable.'
        type: string
      allow-empty:
        description: 'Proceed with the release workflow even if no qualifying changes are detected.'
        type: boolean
        default: false
      dry-run:
        description: 'Simulate the release workflow without modifying files or publishing artifacts.'
        type: boolean
        default: false

permissions:
  contents: write
  id-token: write

env:
  GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  NPM_TOKEN: ${{ secrets.NPM_TOKEN }}
  NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: pnpm/action-setup@v6
      - uses: actions/setup-node@v7
        with:
          node-version: '24'
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile
      - name: Release
        env:
          RELEASE_TYPE: ${{ inputs.type }}
          RELEASE_QUALIFIER: ${{ inputs.qualifier }}
          RELEASE_CHANNEL: ${{ inputs.channel }}
          ALLOW_EMPTY: ${{ inputs['allow-empty'] }}
          DRY_RUN: ${{ inputs['dry-run'] }}
        run: |
          ARGS=()
          if [[ -n "$RELEASE_TYPE" ]]; then ARGS+=(--type "$RELEASE_TYPE"); fi
          if [[ -n "$RELEASE_QUALIFIER" ]]; then ARGS+=(--qualifier "$RELEASE_QUALIFIER"); fi
          if [[ -n "$RELEASE_CHANNEL" ]]; then ARGS+=(--channel "$RELEASE_CHANNEL"); fi
          if [[ "$ALLOW_EMPTY" == "true" ]]; then ARGS+=(--allow-empty); fi
          if [[ "$DRY_RUN" == "true" ]]; then ARGS+=(--dry-run); fi
          npx reelout "${ARGS[@]}"
```

### Notes

- **Permissions:** `contents: write` lets ReelOut push tags and create GitHub releases. `id-token: write` enables npm provenance. Add `packages: write` only if publishing to GitHub Packages.
- **Secrets:** Add `NPM_TOKEN` to repository secrets when publishing to npm. GitHub Actions provides `GITHUB_TOKEN`.
- **Using npm:** Replace the pnpm setup steps with `npm ci` and remove `cache: 'pnpm'`.

## CircleCI

Create `.circleci/config.yml`:

```yaml
version: 2.1
orbs:
  node: circleci/node@7

jobs:
  release:
    macos:
      xcode: '26.6'
    resource_class: m4pro.medium
    steps:
      - checkout
      - node/install:
          node-version: '24'
      - run: corepack enable
      - node/install-packages:
          pkg-manager: pnpm
      - run: npx reelout

workflows:
  release:
    jobs:
      - release:
          context: reelout
          filters:
            branches:
              only: main
```

Set `NPM_TOKEN` and the appropriate hosting token (`GITHUB_TOKEN` or
`GITLAB_TOKEN`) in a shared context or as project environment variables. A
Linux machine executor can be used instead of the macOS executor.

## Shallow checkouts

ReelOut detects shallow repositories and fetches missing history and tags as
needed, so the default `actions/checkout` configuration usually works without
a `fetch-depth` override. If your CI environment restricts `git fetch`, use a
full checkout with `fetch-depth: 0`.

## Debugging in CI

In GitHub Actions, ReelOut enables verbose logging when `RUNNER_DEBUG` or
`ACTIONS_STEP_DEBUG` is truthy. In other CI environments, pass `--debug` to
enable it. See [Troubleshooting](./06-troubleshooting.md).
